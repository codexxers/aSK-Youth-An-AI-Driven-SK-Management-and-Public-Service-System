## FEATURE 1 — "Export Response" Button (Any AI Reply → DOCX or PDF)

### What it does
A small export icon button appears on every completed AI assistant message (not during streaming). When hovered, a tooltip reads **"Export Response"**. Clicking it opens a small modal/popup asking the user to choose between **Export to PDF** or **Export to DOCX**. The exported file uses the SK official letterhead layout (same as the existing `/api/export/document` endpoint). If the AI reply contains an `<official_document>` block, the exported content is the document content only (same as today). If the AI reply is a plain conversational reply (no `<official_document>` tag), the full reply text is exported with the SK letterhead.

### UI Specification

**Button appearance:**
- Small icon button (24×24 px or similar), positioned at the bottom-right corner of the AI message bubble action row — same row as the existing thumbs-up / copy / thinking panel toggles if they exist, otherwise a standalone icon row below the bubble.
- Icon: use an arrow-pointing-up-out-of-a-box SVG (upload/export icon), similar to the Gemini "Export to Docs" style in the reference screenshot. Do NOT use a download arrow — use an outward export arrow.
- On hover: show a tooltip that reads **"Export Response"** (dark background tooltip, white text, rounded corners, 150ms delay).
- Button color: neutral (gray), with a subtle cyan highlight on hover to match the system's existing cyan accent.

**Click behavior:**
1. Clicking the button opens a small popup/modal anchored near the button (not a full-screen modal — a compact dropdown or small card, ~200px wide).
2. The popup contains:
   - A small header: **"Export as..."**
   - Two buttons, each with its own icon:
     - 📄 **Export to DOCX** (blue, matches existing DOCX button style)
     - 🖨️ **Export to PDF** (cyan, matches existing PDF button style)
   - An **×** close button in the top-right corner of the popup.
3. If the AI reply text is empty or the message is still streaming → the export button must NOT appear. Only show on fully completed messages.

**When there is no `<official_document>` block in the reply:**
- The full `content` of the assistant message is sent as the document body.
- The exported document must use the SK letterhead and wrap the reply content cleanly (no raw markdown symbols — strip `**`, `##`, `###`, `*` before exporting).
- Add a note line at the bottom of the exported file: *"Generated by aSK Youth AI Assistant — Barangay Concepcion Dos, Marikina City"*

**When there IS an `<official_document>` block:**
- Extract and use the document content only (existing behavior of `handleExport()` — reuse that logic).
- The new export button calls the same `/api/export/document` endpoint with the same payload as the existing Export panel buttons. Do not duplicate the endpoint.

### Backend — No New Routes Required
The existing `POST /api/export/document` endpoint already handles both DOCX and PDF. The new button reuses it exactly. The only addition: when the content passed is plain-text (non-document), strip markdown formatting server-side before handing it to `docx`/`pdfkit`:

In `server.js`, inside the `/api/export/document` handler, add this helper **only if it does not already exist**:
```js
function stripMarkdown(text) {
  return text
    .replace(/#{1,6}\s?/g, '')       // headers
    .replace(/\*\*(.*?)\*\*/g, '$1') // bold
    .replace(/\*(.*?)\*/g, '$1')     // italic
    .replace(/`{1,3}[^`]*`{1,3}/g, '') // code
    .replace(/\[([^\]]+)\]\([^)]+\)/g, '$1') // links
    .trim();
}
```
Apply `stripMarkdown()` to the `content` field before passing it to the document generators — but only when the `isPlainReply` flag is `true` in the request body. Add `isPlainReply` as an optional boolean field to the existing export request body. Default: `false`. When `false`, existing behavior is completely unchanged.

**Export document layout for plain replies (isPlainReply: true):**
Follow the exact same SK letterhead structure used for official documents:
```
Republic of the Philippines
City of Marikina
Barangay Concepcion Dos
OFFICE OF THE SANGGUNIANG KABATAAN

[Stripped reply content here]

---
Generated by aSK Youth AI Assistant
Barangay Concepcion Dos, Marikina City
```

## FEATURE 2 — Document Source Match Panel Revival

### Background
This feature previously existed and was lost in an update. The backend already streams `retrievedChunks` in the `done` SSE event. The frontend already has styling hooks for a Sources panel. The task is to ensure the scoring logic is correct and the UI panel is reliably rendered.

### How It Works (End-to-End)

**Backend (already implemented — verify it is intact):**
The `done` SSE event already includes `retrievedChunks`. Each chunk has at minimum: `{ source, text, score }` where `score` is the cosine similarity (0.0–1.0).

Verify in `server.js` that the `done` event sends:
```js
sendEvent('done', {
  ai_data: fullReply,
  documents: documentsData,
  retrievedChunks: retrievedChunks   // ← this must be present
});
```
If `retrievedChunks` is missing from the `done` payload, add it. Do not change anything else in the `done` event structure.

**Relevance Score Calculation — 2-Phase Approach:**

The raw cosine similarity from HNSW gives a base signal, but it can be noisy. Add a second scoring phase (Phase 2) that adjusts the displayed percentage shown to the user:

**Phase 1 — Raw cosine similarity** (already done by HNSW searchKnn):
- This is `chunk.score` (value between 0.0 and 1.0).
- Chunks below 0.20 are already discarded in the RAG pipeline — keep this threshold.

**Phase 2 — Display relevance weighting** (new, in frontend or lightweight in backend):
Apply a simple display adjustment to make percentages more meaningful to SK officials:

```
displayScore = clamp(rawScore * 1.15, 0, 1.0)   // mild boost for UI readability
```

Then map `displayScore` to a percentage: `Math.round(displayScore * 100)`.

**Show in Sources panel only if:** `displayScore >= 0.30` (30% minimum to appear in sources dropdown).

**Background color of the sources panel header** (the collapsed summary row):
- `displayScore >= 0.90` → background: `#14532d` (deep green) + white text — "Very High Match"
- `displayScore >= 0.70` → background: `#166534` → green + "High Match"  
- `displayScore >= 0.50` → background: `#854d0e` → amber/yellow + "Moderate Match"
- `displayScore >= 0.30` → background: `#374151` → gray + "Low Match"

The background color reflects the **highest-scoring source** found. If no sources pass 30%, the Sources panel does not render at all for that message.

**3-Phase Prompt Architecture for Source Relevance:**

When calculating what to show in the Sources panel, use this logic (all in the existing pipeline):

- **Phase A (Retrieval):** HNSW searchKnn retrieves top-K chunks by raw cosine similarity. Threshold: ≥ 0.20 to be kept in context. Already implemented.
- **Phase B (Display Filter):** Of the kept chunks, only show in Sources panel those with `displayScore ≥ 0.30`. This prevents showing barely-relevant sources that might mislead users.
- **Phase C (Smartness check):** If the user's query is classified as casual (`isCasualQuery()` returned true and RAG was skipped), the Sources panel must NOT render at all — there were no retrieved chunks because none were needed.

### Frontend — Sources Panel UI Specification

**Per assistant message**, after the message bubble, render a Sources panel **only when** `message.retrievedChunks` exists and has at least one chunk with `displayScore >= 0.30`.

**Collapsed state (default):**
```
[ 📄 SOURCES (N) ▼ ]
```
- The `N` = number of qualifying sources.
- Background color = based on top-scoring source (see color map above).
- The entire row is clickable to expand/collapse.
- A small badge shows the top match percentage: e.g., `60% match` in a colored pill (green/yellow/gray based on score band).

**Expanded state:**
Each source is shown as a row:
```
[ 📄 Doc4_MasterPlan.docx          60% match ]
  ▶ View Snippet
```
- Clicking "View Snippet" expands an inline code-style box showing the raw chunk text (truncated to ~300 chars with "..." if longer).
- Each source row's match percentage pill uses the same color bands:
  - ≥ 70% → green pill
  - ≥ 50% → yellow/amber pill
  - ≥ 30% → gray pill
- The same file can appear multiple times if multiple chunks from it were retrieved — group by filename and show the **highest** score for that file. List each unique filename once.

**Reference screenshot:** The image provided shows the exact layout target — dark background, filename + match %, expandable "View Snippet". Match this styling using the system's existing Tailwind dark theme colors (`bg-gray-800`, `bg-gray-700`, etc.).

**Color for the Sources row background (based on top score):**
```jsx
const topScore = Math.max(...qualifyingChunks.map(c => c.displayScore));
const panelBg =
  topScore >= 0.90 ? 'bg-green-900' :
  topScore >= 0.70 ? 'bg-green-800' :
  topScore >= 0.50 ? 'bg-yellow-900' :
  'bg-gray-700';
```

**Sources panel must NOT appear when:**
- The message has no `retrievedChunks` (casual query, event query with no RAG, or new conversation).
- All chunks have `displayScore < 0.30`.
- The message is still streaming.

### Data Flow — Where to Store `retrievedChunks`
